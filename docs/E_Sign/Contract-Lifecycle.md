# How to use contract Lifecycle Management?

**Contract Lifecycle Management (CLM)** helps organizations create, review, approve, sign, store, and manage contracts throughout their entire lifecycle. It streamlines contract processes, improves visibility, and ensures compliance by keeping all contract-related activities in a centralized system.

---

## Step 1: Create a New Contract

1. Navigate to **Documents** from the main dashboard.
2. Click **Create**.
3. Select the appropriate **Generate with AI or Manually**.
4. Enable the **ClM Option** in the Task Bar.

## Step 2: CLM Review Process

The **CLM Review panel** (accessible via the CLM Review button in the top toolbar) manages the complete contract review lifecycle.

**Review Panel Tabs**

| Tab | Purpose |
|-------|---------|
| Comments | View and manage inline document comments |
| Redlines | Track suggested edits and tracked changes |
| Review | Manage approval workflow, view activity timeline |

- In the **right-side panel**, click the **Send for Review** button to initiate the document review and sending process.

## Step 3: Save the Document and Create a Contract 

#### 1. Save the Document

After initiating the document sending process, the system prompts you to save the document.

## Step 4: Send Process of the Document 

**Add Reviewers**
- Enter reviewer Name and Email for each participant.
- Assign a **Role** from the dropdown:
   - **Viewer** — Read-only access; can view the document but cannot annotate.
   - **Commenter** — Can add inline comments and annotations.
- Use **+ Add Another Reviewer** to include additional participants.
- Click Next to proceed.
- The contract document is sent to the reviewers via email for review and feedback.

<img src=" screenshots\CLM\CLM6.png" style="border:2px solid black; border-radius:4px; width:100%; max-width:800px;" alt="Screenshot for Document">

### Document Lock During Review

- Once the document is sent for review, it enters the review process and the sender can no longer edit the document. 
- The document editing option is automatically disabled to prevent changes while reviewers are providing feedback. 
- After the review process is completed and all feedback is received, the editing option is automatically re-enabled, allowing the sender to update the document as needed.

<img src=" screenshots\CLM\CLM7.png" style="border:2px solid black; border-radius:4px; width:100%; max-width:800px;" alt="Screenshot for Document">

## Step 5: Reviewer Open the Document

1. The reviewer opens the contract document through the email link provided.
2. Open the document and complete the OTP verification process to proceed.
3. The contract review experience and permissions are determined based on the reviewer's assigned **role**.
4. The contract review process supports two reviewer roles:
- **Viewer** — Has read-only access and can review the document content but cannot add comments or annotations.
- **Commenter** — Can review the document and add inline comments, annotations, and feedback for the sender.

<!-- <img src=" screenshots\CLM\CLM-1.png" style="border:2px solid black; border-radius:4px; width:100%; max-width:800px;" alt="Screenshot for Document"> -->

### Viewer Role

The **Viewer** role allows recipients to review the document, add redline suggestions, and reply to existing comments. Viewers cannot create new comments or annotations.

* **Review Document** — Viewer role can open and review the document in read-only mode.
* **Comment Restrictions** — Viewers cannot create new comments or annotations in the document.
* **Reply to Comments** — Viewers can reply to existing comments posted by commenters in the comment section.

<img src=" screenshots\CLM\CLM-Viewer.png" style="border:2px solid black; border-radius:4px; width:100%; max-width:800px;" alt="Screenshot for Document">

### Commenter Role

The **Commenter** role allows recipients to review the document, add inline comments and annotations, reply to existing comments, and provide feedback through redline suggestions. This role is intended for users who need to actively participate in the document review and negotiation process.

* **Review Document** — Commenters can review the document, select specific content, add inline comments, and submit redline suggestions for proposed changes.
* **Reply to Comments** — Commenters can reply to existing comments and participate in discussions within the comment section.
* **Add Annotations** — Commenters can provide detailed feedback and recommendations directly within the document review interface.

<img src=" screenshots\CLM\CLM-Commenter.png" style="border:2px solid black; border-radius:4px; width:100%; max-width:800px;" alt="Screenshot for Document">

## Step 6: Document Return Process

The **Document Return Process** enables reviewers to provide feedback, propose modifications, and return the reviewed document to the sender for further evaluation. During this process, reviewers can add comments, create redline suggestions, negotiate contract terms, or reject the document if necessary.

Once the review is complete, the reviewer can return the document with all associated feedback, allowing the sender to review the proposed changes and take appropriate action.

### 1. Add Comments

Comments allow reviewers to provide contextual feedback on specific sections of the document.

1. Review the document content carefully.
2. Select the required text, paragraph, or clause.
3. Add comments and feedback using the comment feature.
4. Save the comment.

The comments are shared with the sender and become available for review, discussion, and resolution.

> **Viewers can reply to existing comments but cannot create new comments or annotations within the document.**

### 2. Review and Customize Redline Suggestions

The **Redline** feature helps reviewers analyze document content and propose contract modifications.

1. Click the **Redline** button.
2. Review the AI-generated redline suggestions.
3. Analyze the proposed modifications.
4. Customize, accept, or modify the suggested changes as required.
5. Save the redline recommendations.

This feature helps streamline contract negotiations and ensures that all proposed revisions are clearly documented.

### 3. Return the Document

After completing the review process:

1. Click **Return**.
2. Review the comments, feedback, and redline suggestions.
3. Submit the document back to the sender.

The document, along with all comments, negotiation feedback, and proposed revisions, is returned to the sender for further review and action.

### 4. Reject the Document

Click the **Reject** button to decline the document. A confirmation pop-up will appear, allowing the reviewer to provide a rejection reason. Once submitted, the rejection status and feedback will be sent to the sender via the document review portal and email notification.

## Step 7: Sender Review Process

### Overview

After **reviewers** complete the document review process, the contract is returned to the sender along with all comments, redline suggestions, approvals, and negotiation feedback. The sender can review the feedback, update the document, verify the changes, and proceed to the next stage of the contract lifecycle.


#### 1. Receive the Returned Document

Once the review process is completed, the sender receives a notification email containing the reviewed document and reviewer feedback.

1. Open the notification email.
2. Click the document link to access the returned contract.

<img src="screenshots/CLM/CLM-Viewer-Return-Mail.png" style="border:2px solid black; border-radius:4px; width:100%; max-width:800px;" alt="Returned Document Email Notification">


#### 2. Review Reviewer Feedback

The **sender** can access all comments, annotations, redline suggestions, approvals, and negotiation feedback submitted during the review process.

1. Open the **returned** document.
2. Review all comments and discussion threads.
3. Examine the feedback provided by reviewers.

<img src="screenshots/CLM/CLM-Sender-Review.png" style="border:2px solid black; border-radius:4px; width:100%; max-width:800px;" alt="Review Reviewer Feedback">


#### 3. Analyze Proposed Changes

Review and evaluate all suggested modifications before updating the document.

1. Review **redline** suggestions.
2. Compare the proposed changes with the current document **version**.
3. Analyze negotiation recommendations.
4. Determine which changes should be accepted, modified, or rejected.

<img src="screenshots/CLM/CLM-Sender-Review1.png" style="border:2px solid black; border-radius:4px; width:100%; max-width:800px;" alt="Analyze Proposed Changes">


#### 4. Update the Contract Document

After reviewing the feedback, update the contract accordingly.

1. Open the document in edit mode.
2. Apply approved comments and redline suggestions.
3. Modify contract clauses and content as required.
4. Save the updated document.

<img src="screenshots/CLM/CLM-Sender-Review2.png" style="border:2px solid black; border-radius:4px; width:100%; max-width:800px;" alt="Update Contract Document"><br>

<img src="screenshots/CLM/CLM-Sender-Review3.png" style="border:2px solid black; border-radius:4px; width:100%; max-width:800px;" alt="Updated Contract Document"><br>

<img src="screenshots/CLM/CLM-Sender-Review4.png" style="border:2px solid black; border-radius:4px; width:100%; max-width:800px;" alt="Document Comparison View"><br>

<img src="screenshots/CLM/CLM-Sender-Review5.png" style="border:2px solid black; border-radius:4px; width:100%; max-width:800px;" alt="Document Comparison View">


#### 5. Verify Changes Using Document Comparison

Before resending the document, the system automatically creates a new version and opens the comparison view.

1. Open the comparison view.
2. Compare the latest version with the previous version.
3. Review all accepted changes and modifications.
4. Verify that the updated content reflects the intended revisions.

<img src="screenshots\CLM\CLM-Auto-Compare.png" style="border:2px solid black; border-radius:4px; width:100%; max-width:800px;" alt="Screenshot for Document">

## Step 10: Configure E-Sign Document

* After the document is approved, the sender receives the approved document via email.
* Review the approved document and click the **E-Sign** icon in the taskbar to open the E-Sign Editor.
* Add the required signature fields, date fields, and other signing elements to the contract document.
* Verify the signer details and field placements.
* Send the contract document to all designated parties via email for the electronic signing process.

<img src="screenshots\CLM\CLM-Sender-Approval.png" style="border:2px solid black; border-radius:4px; width:100%; max-width:800px;" alt="Screenshot for Document">

## Step 11: Configure Signature Process

* Select Send for Signature to initiate the e-signature workflow.
* Add the required signers and recipients for the contract.
* Configure notification and reminder settings as needed.
* Review the signer details and document fields.
* Click Send to deliver the contract to all designated parties via email for the signing process.
